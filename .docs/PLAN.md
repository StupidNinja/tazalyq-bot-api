# Техническое задание

## Telegram-бот для сбора обращений о мусоре и незаконных свалках

## 1. Назначение проекта

Необходимо разработать Telegram-бота для сбора обращений от жителей города Кызылорда о мусоре, незаконных свалках и загрязнённых участках.

Пользователь должен иметь возможность отправить фото проблемы, указать геопозицию или адрес, добавить описание и получить номер обращения. Администраторы должны получать обращения в отдельный Telegram-чат, менять статус обращения и уведомлять пользователя о ходе обработки.

Сервис должен быть подготовлен к локальному запуску и дальнейшему развёртыванию на сервере. Приложение и связанные сервисы должны запускаться в контейнерах.

---

## 2. Цели MVP

MVP должен показать полный рабочий цикл:

1. Пользователь запускает бота.
2. Выбирает язык: казахский или русский.
3. Вводит ФИО.
4. Отправляет номер телефона.
5. Создаёт обращение.
6. Прикрепляет фото мусора или незаконной свалки.
7. Указывает геопозицию или адрес.
8. Добавляет описание.
9. Подтверждает отправку обращения.
10. Администраторы получают обращение в Telegram-чате.
11. Администратор меняет статус обращения.
12. Пользователь получает уведомление об изменении статуса.
13. Данные сохраняются в PostgreSQL.
14. Фото сохраняются в Cloudflare R2.

## 4. Роли пользователей

В системе должны быть следующие роли:

### 4.1. Обычный пользователь

Обычный пользователь может:

- выбрать язык интерфейса;
- ввести ФИО;
- отправить номер телефона;
- создать обращение;
- прикрепить одно или несколько фото;
- отправить геопозицию или указать адрес текстом;
- добавить описание проблемы;
- подтвердить или отменить обращение;
- посмотреть свои обращения;
- получать уведомления об изменении статуса обращения.

### 4.2. Администратор

Администратор может:

- получать новые обращения в админском Telegram-чате;
- просматривать фото, адрес, геопозицию и описание обращения;
- брать обращение в работу;
- закрывать обращение;
- отклонять обращение;
- видеть краткую статистику;
- отправлять пользователю уведомления через изменение статуса.

### 4.3. Супер-администратор

Для MVP можно не делать отдельный интерфейс супер-администратора.

На первом этапе список администраторов можно хранить в `.env`:

```env
ADMIN_IDS=123456789,987654321
ADMIN_CHAT_ID=-1001234567890
```

Позже можно вынести администраторов в отдельную таблицу.

Пример:

Выбранный язык сохраняется в профиле пользователя.

```text

```

## 6. Первичная регистрация пользователя

После выбора языка бот должен запросить ФИО.

### 6.1. Ввод ФИО

Бот:

```text
Введите ваше ФИО.
Например: Иванов Иван Иванович
```

Пользователь вводит текст.

ФИО сохраняется в базе данных.

Минимальная валидация:

- не пустая строка;
- минимум 2 слова желательно, но не обязательно блокировать пользователя;
- длина не более 255 символов.

### 6.2. Ввод номера телефона

После ФИО бот должен запросить номер телефона.

Лучший вариант — использовать Telegram-кнопку отправки контакта.

Бот:

```text
Отправьте ваш номер телефона.
Нажмите кнопку ниже или введите номер вручную.
```

Кнопка:

```text
📱 Отправить номер телефона
```

Если пользователь отправляет контакт, бот сохраняет номер телефона.

Если пользователь вводит номер вручную, бот должен принять текст и сохранить его.

Минимальная валидация:

- разрешить номера формата `+7...`, `8...`, `7...`;
- убрать пробелы, дефисы и скобки;
- сохранить нормализованный номер, если возможно.

После сохранения ФИО и телефона пользователь попадает в главное меню.

## 8. Flow создания обращения

### 8.1. Начало создания обращения

Пользователь нажимает:

```text
🗑 Создать обращение
```

Бот создаёт черновик обращения со статусом `DRAFT`.

Бот просит отправить фото:

```text
Отправьте фото мусора или незаконной свалки.
Можно отправить одно или несколько фото.
```

Кнопка:

```text
❌ Отменить
```

---

### 8.2. Добавление фото

Пользователь отправляет одно или несколько фото.

Система должна:

1. Получить `file_id` фото из Telegram.
2. Скачать фото через Telegram Bot API.
3. Загрузить фото в Cloudflare R2.
4. Сохранить информацию о фото в PostgreSQL.
5. Привязать фото к текущему обращению.

После каждого фото бот отвечает:

```text
Фото добавлено.
Вы можете отправить ещё фото или нажать "Далее".
```

Кнопки:

```text
➡️ Далее
❌ Отменить
```

Минимальное требование:

- минимум 1 фото обязательно;
- максимум фото на MVP: 5 штук на одно обращение.

Если пользователь нажимает “Далее” без фото, бот должен попросить сначала отправить фото.

---

### 8.3. Указание места

После фото бот просит указать место.

Бот:

```text
Теперь отправьте геопозицию места, где находится мусор.

Если вы уже не на месте, можете ввести адрес текстом.
```

Кнопки:

```text
📍 Отправить геопозицию
✍️ Ввести адрес текстом
❌ Отменить
```

Пользователь может:

1. отправить Telegram location;
2. написать адрес текстом.

Если пользователь отправил геопозицию, сохранить:

- latitude;
- longitude.

Если пользователь ввёл адрес, сохранить:

- address_text.

Геокодинг адреса в координаты для MVP не требуется.

---

### 8.4. Описание проблемы

После указания места бот просит описание.

Бот:

```text
Добавьте короткое описание проблемы.

Например:
"Незаконная свалка возле дороги, мусор лежит несколько недель."
```

Кнопки:

```text
Пропустить
❌ Отменить
```

Описание можно сделать необязательным.

Если пользователь нажал “Пропустить”, сохранить `description = null`.

---

### 8.5. Предпросмотр обращения

Перед отправкой бот показывает пользователю итоговую информацию.

Пример:

```text
Проверьте обращение:

Фото: 2 шт.
Место: ул. Абая, возле дома 15
Описание: Незаконная свалка возле дороги.

Отправить обращение?
```

Кнопки:

```text
✅ Отправить
✏️ Изменить место
📝 Изменить описание
🖼 Изменить фото
❌ Отменить
```

Для первой версии допустимо реализовать только:

```text
✅ Отправить
❌ Отменить
```

---

### 8.6. Отправка обращения

После нажатия “Отправить” система должна:

1. изменить статус обращения `DRAFT` → `NEW`;
2. сохранить `submitted_at`;
3. отправить обращение в админский Telegram-чат;
4. отправить пользователю подтверждение.

Пользователь получает:

```text
Обращение #124 принято.

Статус: Новое

Спасибо! Ваше обращение передано ответственным лицам.
```

## 9. Админский flow

### 9.1. Получение нового обращения

После отправки обращения пользователем бот должен отправить карточку обращения в админский Telegram-чат.

Пример сообщения:

```text
🗑 Новое обращение #124

Дата: 23.06.2026 12:40

Заявитель:
ФИО: Иванов Иван Иванович
Телефон: +77001234567
Telegram: @username
Telegram ID: 123456789

Место:
ул. Абая, возле дома 15

Гео:
https://maps.google.com/?q=44.8479,65.4999

Описание:
Незаконная свалка возле дороги, мусор лежит несколько недель.

Фото: 2 шт.

Статус: Новое
```

Кнопки под сообщением:

```text
👀 В работу
✅ Закрыть
❌ Отклонить
```

Фото должны быть отправлены в админский чат вместе с обращением или отдельными сообщениями перед карточкой обращения.

---

### 9.2. Взять обращение в работу

Когда админ нажимает:

```text
👀 В работу
```

Система должна:

1. проверить, что пользователь является админом;
2. изменить статус обращения `NEW` → `IN_PROGRESS`;
3. сохранить ID администратора;
4. добавить запись в историю статусов;
5. обновить сообщение в админском чате;
6. уведомить пользователя.

Пользователь получает:

```text
Статус обращения #124 изменён.

Новый статус: В работе.
```

---

### 9.3. Закрыть обращение

Когда админ нажимает:

```text
✅ Закрыть
```

Система должна:

1. проверить права администратора;
2. изменить статус обращения на `RESOLVED`;
3. сохранить время закрытия;
4. добавить запись в историю статусов;
5. обновить сообщение в админском чате;
6. уведомить пользователя.

Пользователь получает:

```text
Обращение #124 закрыто.

Спасибо за обращение.
```

На MVP комментарий при закрытии можно не требовать.

---

### 9.4. Отклонить обращение

Когда админ нажимает:

```text
❌ Отклонить
```

Система должна показать причины отклонения:

```text
Выберите причину отклонения:
```

Кнопки:

```text
Недостаточно информации
Не относится к мусору
Некорректное фото
Дубликат обращения
Адрес не найден
```

После выбора причины система должна:

1. изменить статус обращения на `REJECTED`;
2. сохранить причину отклонения;
3. добавить запись в историю статусов;
4. обновить сообщение в админском чате;
5. уведомить пользователя.

Пользователь получает:

```text
Обращение #124 отклонено.

Причина:
Недостаточно информации.
```

## 12. Статусы обращения

Использовать следующие статусы:

```text
DRAFT        — черновик, пользователь ещё заполняет обращение
NEW          — новое обращение отправлено
IN_PROGRESS  — обращение взято в работу
RESOLVED     — обращение закрыто
REJECTED     — обращение отклонено
CANCELLED    — пользователь отменил создание обращения
```

## 15. Cloudflare R2

Фото обращений должны сохраняться в Cloudflare R2.

### 15.1. Структура хранения файлов

Рекомендуемая структура ключей:

```text
reports/{year}/{month}/{day}/report-{reportId}/{photoId}.jpg
```

Пример:

```text
reports/2026/06/23/report-124/photo-1.jpg
```

### 15.2. Настройки через env

```env
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=
R2_ENDPOINT=
R2_PUBLIC_BASE_URL=
```

Если bucket приватный, `R2_PUBLIC_BASE_URL` не обязателен.

### 15.3. Доступ к фото

Для MVP допустимо:

1. отправлять фото в админский Telegram-чат напрямую;
2. хранить фото в R2 как архив;
3. не делать публичные ссылки на фото.

Для production желательно использовать приватный bucket и signed URLs.

## 16. Docker и инфраструктура

Сервис должен запускаться через Docker Compose.

Минимальные контейнеры:

```text
app        — NestJS-приложение с Telegram-ботом
postgres   — база данных PostgreSQL
```

Cloudflare R2 является внешним сервисом и отдельным контейнером не запускается.

### 16.1. docker-compose.yml

Состав:

```text
app
postgres
```

`app` должен зависеть от `postgres`.

PostgreSQL должен использовать volume для сохранения данных.

### 16.2. Пример env-переменных

```env
NODE_ENV=development
PORT=3000

BOT_TOKEN=
BOT_MODE=polling

ADMIN_IDS=
ADMIN_CHAT_ID=

DATABASE_URL=postgresql://postgres:postgres@postgres:5432/garbage_bot

R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=
R2_ENDPOINT=
R2_PUBLIC_BASE_URL=
```

## 19. Валидация

### Фото

- минимум 1 фото;
- максимум 5 фото;
- принимать только изображения;
- если пользователь отправил не фото, попросить отправить фото.

### ФИО

- обязательное поле;
- максимум 255 символов.

### Телефон

- обязательное поле;
- принимать Telegram contact;
- принимать ручной ввод;
- нормализовать номер при возможности.

### Локация

Обязательно одно из двух:

- геопозиция;
- адрес текстом.

### Описание

- необязательное поле;
- максимум 1000 символов.

## 20. Логирование и ошибки

Система должна логировать:

- запуск приложения;
- подключение к базе данных;
- ошибки Telegram Bot API;
- ошибки загрузки фото в R2;
- создание обращения;
- изменение статуса обращения;
- ошибки отправки сообщений пользователям и админам.

Если фото не удалось загрузить в R2, бот должен сообщить пользователю:

```text
Не удалось сохранить фото. Попробуйте отправить его ещё раз.
```

Если обращение не удалось отправить администраторам:

```text
Обращение сохранено, но возникла ошибка при отправке администраторам. Мы обработаем его позже.
```

## 21. Нефункциональные требования

### 21.1. Надёжность

- данные обращений должны сохраняться в PostgreSQL;
- фото должны сохраняться в Cloudflare R2;
- при перезапуске приложения черновики и отправленные обращения не должны теряться.

### 21.2. Безопасность

- токен Telegram-бота хранить только в `.env`;
- ключи Cloudflare R2 хранить только в `.env`;
- не коммитить `.env` в Git;
- проверять права администратора при нажатии админских кнопок;
- не показывать обращения другим пользователям;
- пользователь должен видеть только свои обращения.

### 21.3. Масштабируемость

Архитектура должна позволять в будущем добавить:

- веб-админку;
- карту обращений;
- экспорт Excel/PDF;
- распределение обращений по районам;
- роли для разных организаций;
- комментарии админов;
- публичный статус обращения;
- webhook-режим Telegram-бота;
- деплой на VPS.

## 22. Приоритет разработки

### Этап 1. Базовая инфраструктура

1. Поднять NestJS-приложение.
2. Подключить PostgreSQL.
3. Настроить Dockerfile.
4. Настроить docker-compose.
5. Добавить `/health`.
6. Подключить Telegram-бота.

### Этап 2. Регистрация пользователя

1. `/start`.
2. Выбор языка.
3. Ввод ФИО.
4. Ввод телефона.
5. Главное меню.

### Этап 3. Создание обращения

1. Создание `DRAFT` обращения.
2. Приём фото.
3. Загрузка фото в Cloudflare R2.
4. Приём геопозиции или адреса.
5. Приём описания.
6. Предпросмотр обращения.
7. Подтверждение отправки.

### Этап 4. Админский flow

1. Отправка обращения в админский чат.
2. Кнопка “В работу”.
3. Кнопка “Закрыть”.
4. Кнопка “Отклонить”.
5. Уведомления пользователю.
6. История изменения статусов.

### Этап 5. Дополнительные функции

1. “Мои обращения”.
2. “Помощь”.
3. “Изменить язык”.
4. `/stats` для админов.

## 23. Критерии готовности MVP

MVP считается готовым, если:

1. Проект запускается через Docker Compose.
2. NestJS-приложение подключается к PostgreSQL.
3. Telegram-бот запускается в polling-режиме.
4. Пользователь может выбрать язык.
5. Пользователь может ввести ФИО.
6. Пользователь может отправить номер телефона.
7. Пользователь может создать обращение.
8. Пользователь может отправить фото.
9. Фото сохраняется в Cloudflare R2.
10. Пользователь может указать геопозицию или адрес.
11. Пользователь может добавить описание.
12. Пользователь может подтвердить отправку.
13. Обращение сохраняется в PostgreSQL.
14. Админы получают обращение в Telegram-чате.
15. Админ может изменить статус обращения.
16. Пользователь получает уведомление об изменении статуса.
17. Пользователь может посмотреть свои обращения.
18. Админ может посмотреть краткую статистику.
